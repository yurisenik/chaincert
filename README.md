# Chaincert

[Проверить цепочку TLS](https://chaincert.d.senik.su/). Публичный экземпляр подключается из России. Можно узнать, какие сертификаты отправляет сервер во время TLS-рукопожатия, и скачать проверенную цепочку для установки. Это независимая реализация, вдохновлённая [What's My Chain Cert?](https://whatsmychaincert.com/).

Введите имя хоста (например, `example.org:8443`) или вставьте публичный сертификат в PEM. По умолчанию используется порт 443. При необходимости сервис ищет промежуточные сертификаты по ссылкам AIA и проверяет путь до корневого сертификата из системного хранилища. Ответ различает исходную цепочку и собранную. Файл `fullchain.pem` начинается с сертификата сервера. Корневой сертификат можно добавить отдельным флажком.

Ссылка `/?host=example.org%3A8443` запускает проверку адреса при открытии. Поддерживаются домены на кириллице. Кнопка «Скопировать ссылку» под результатом позволяет поделиться адресом для новой проверки. Ссылка содержит только адрес сервера. PEM и настройки проверки в неё не попадают. Параметры вроде `utm_source` игнорируются. Пустой или повторяющийся `host` показывает ошибку без отправки запроса.

Проверка имени выполняется при подключении к хосту. Режим PEM принимает сертификаты без приватного ключа. Диагностика рассчитана на непосредственное соединение по TLS 1.2 или 1.3. В форме можно вводить домены на кириллице, в HTTP API используйте punycode. STARTTLS, ГОСТ TLS и проверка отзыва по OCSP/CRL в неё не входят. Результат зависит от корневых сертификатов на узле и доступности издателей по AIA.

## Запуск

```sh
docker build -t chaincert .
docker run --rm -p 127.0.0.1:8080:8080 chaincert
```

Для публикации за Traefik используйте [пакет dcape](https://github.com/yurisenik/dcape-app-chaincert). При развёртывании в контейнере задайте переменную `CHAINCERT_DENY_IPS` со списком публичных IP самого Docker-узла через запятую. Сервис ограничивает параллельные проверки, размер запроса и время операций. Приложение не ведёт журнал адресов проверяемых серверов и содержимого PEM.

Переменная `CHAINCERT_PROBE_LABEL` задаёт полное предложение об узле, с которого выполняется проверка, например `Подключение выполняется с сервера в России.` Указывайте фактическое расположение своего экземпляра. Без переменной или при пустом значении отображается `Проверка выполняется с сервера Chaincert.` Текст читается при запуске, выводится как обычный текст с HTML-экранированием и доступен без JavaScript как на `/`, так и на `/index.html`. Для изменения текста перезапустите приложение. Эта настройка меняет только описание на странице, а не сетевой маршрут проверки.

```sh
docker run --rm -p 127.0.0.1:8080:8080 \
  -e CHAINCERT_PROBE_LABEL='Подключение выполняется с сервера в России.' \
  chaincert
```

## HTTP API

```sh
curl -fsS http://127.0.0.1:8080/healthz
curl -sS http://127.0.0.1:8080/api/check \
  -H 'Content-Type: application/json' \
  -d '{"host":"example.org","includeRoot":false}'
```

Для проверки PEM передайте `certPEM` вместо `host`. Поле `status` принимает значения `ok`, `warning` или `error`. Поле `presented` описывает исходные сертификаты, `issues` — отдельные замечания, `chain` — построенный путь. Если цепочку удалось собрать и проверить, в поле `pem` возвращается её содержимое.
